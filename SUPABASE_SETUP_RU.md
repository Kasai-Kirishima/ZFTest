# Подключение Supabase — Zero Football v62

## Актуально для v66

- Матчи теперь состоят из 12 эпизодов. В обычных эпизодах доступно до 8 вариантов атаки и защиты.
- После уже выполненных миграций `001`, `002` и `003` один раз выполни `supabase/004_twelve_match_events.sql` в SQL Editor. Она разрешает 12 событий и сохраняет совместимость со старыми комнатами на 10 событий.
- Для одиночных матчей миграция `004` не требуется.

## Что изменилось
- При запуске первым открывается экран регистрации или входа. Есть отдельная кнопка продолжения без входа — она оставляет доступ только к одиночному режиму.
- После входа появляется обычное меню клуба; одиночные матчи против ботов сохранены.
- Добавлен раздел **Мультиплеер**: приватные комнаты по коду приглашения и открытый список комнат.
- Быстрый матч использует ту же кнопку, что и одиночный режим: поиск реального соперника длится до 30 секунд, затем автоматически запускается матч с ботом.
- Онлайн-матч состоит из 12 общих эпизодов: в каждом оба игрока видят одно событие, один выбирает атаку, второй — защиту; роли чередуются.
- В эпизоде с пенальти у бьющего и вратаря по шесть вариантов направления. Сервер принимает оба решения и один раз рассчитывает результат.
- Регистрация, вход и сессия работают через Supabase Auth.
- Облачное сохранение перепроверяет действующего пользователя и access token перед записью; RLS не отключается.

## Настройка Supabase — обязательно один раз
1. Открой проект `wakhszvjzzhxyfezpkvl`.
2. Перейди в **SQL Editor** → **New query**.
3. Если таблица облачных сохранений ещё не создавалась, выполни `supabase/001_cloud_saves.sql`.
4. Создай ещё один запрос, вставь весь файл `supabase/002_multiplayer.sql` и нажми **Run**. Он создаёт таблицу онлайн-комнат, безопасные серверные функции для подключения и ходов, RLS-политики и включает события Realtime для таблицы комнат.
5. Создай ещё один запрос, вставь весь файл `supabase/003_quick_match_live.sql` и нажми **Run**. Эта миграция добавляет очередь быстрого поиска, автоматический подбор второго игрока и серверную синхронизацию матчевых событий (до 10 событий до применения миграции `004`).
6. Для версии v66 создай ещё один запрос, вставь весь файл `supabase/004_twelve_match_events.sql` и нажми **Run**. Эта миграция разрешает быстрые онлайн-матчи на 12 эпизодов; старые матчи на 10 эпизодов остаются совместимыми.
7. В **Authentication** → **URL Configuration** укажи адрес сайта Zero Football в **Site URL** и добавь его в **Redirect URLs**. Для локального теста добавь `http://localhost:8000/**`.
8. В **Authentication** → **Providers** проверь, что Email включён. При включённом подтверждении почты после регистрации перейди по ссылке из письма и затем войди.

**Не отключай RLS и не используй `service_role`/secret key в браузере.** В проекте используется только публичный publishable key.

## Запуск локально
Из папки проекта:

`python -m http.server 8000`

Открой `http://localhost:8000`.

## Регистрация и игра
1. При первом запуске появится форма регистрации. Введи свою почту и придумай пароль не короче 6 символов.
2. Если Supabase попросит подтверждение, открой письмо и подтверди адрес. Затем вернись в игру и выбери **Войти**.
3. Создай клуб или выбери уже сохранённый на этом устройстве.
4. Открой **Матчдей** и нажми привычную кнопку **Найти соперника**. Игра ищет второго пользователя 30 секунд. Если подходящий игрок не найден, автоматически открывается матч с ботом.
5. В онлайн-матче оба участника видят одно событие. В каждом эпизоде один выбирает атаку, другой защиту; в следующем эпизоде роли меняются.

## Облачное сохранение
В настройках аккаунта можно вручную отправить локальные клубы в облако или восстановить копию с другого устройства. Загрузка из облака заменяет локальный прогресс целиком — перед этим рекомендуется сохранить резервную копию.

## Ограничения этой версии
- Быстрые онлайн-матчи синхронизируют 12 игровых эпизодов, включая пенальти. Для поиска соперника, авторизации и синхронизации нужен интернет и выполненные SQL-миграции.
- Рейтинг и состав клуба передаются как снимок для отображения; нет рейтингового подбора, чата и античита.
- При желании можно выбрать «Продолжить без входа» — тогда будет доступен только локальный одиночный режим. Старые миграции `001` и `002` повторно запускать не нужно, если они уже применены; для v62 достаточно выполнить `003_quick_match_live.sql`.
